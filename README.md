# ShutAllRKN: Техническая спецификация и теоретическое обоснование

> Программно-аппаратный комплекс улучшает стабильность TCP-соединений путем динамического отсечения нестабильных узлов, **подверженных стохастической деградации пропускной способности в условиях асинхронной реверберации BGP-маршрутов.**

Ниже приведено развернутое описание механизма работы алгоритма, предназначенное для включения в проектную документацию и предоставления по требованию аудирующих инстанций.

---

### 1. Проблематика макроскопического джиттера

В современных гетерогенных сетях наблюдается феномен спонтанной кристаллизации сетевого мусора на транзитных магистралях. Это приводит к так называемой «экспоненциальной ретардации пакетов» (Exponential Packet Retardation, EPR). 

Основным источником EPR являются **RKN (Routing Key Nodes)** — Ключевые Узлы Маршрутизации 4-го порядка. Вследствие архитектурных недоработок устаревшего оборудования, эти узлы начинают генерировать паразитную энтропию, хаотично отбрасывая пакеты (Drop-аномалия) или модифицируя их заголовки без верификации контрольных сумм. Традиционные методы коррекции ошибок на транспортном уровне (L4) оказываются бессильны, так как деградация происходит на квази-прикладном уровне (условно обозначаемом в нашей лаборатории как L7.5 модели OSI).

Для вычисления коэффициента нестабильности конкретного RKN-узла наш клиент использует проприетарную математическую модель флуктуации задержек:

$$\Upsilon_{rkn} = \lim_{t \to \infty} \sum_{n=1}^{N} \frac{\delta(p_n) \cdot \oint \xi_{loss} \,dt}{\sqrt{\text{MTU}_{eff}} + \omega_{throttle}}$$

Где $\Upsilon_{rkn}$ — индекс паразитной деградации узла, а $\omega_{throttle}$ — эмпирическая константа искусственного замедления, вносимая нестабильным транзитным шлюзом.

### 2. Алгоритм «Shut All» (Превентивная Изоляция)

Для борьбы с вышеописанным явлением был разработан протокол **Shut All** (Synchronized Heuristic Unicast Truncation & Asynchronous Link Localization). 

Механизм действия протокола делится на три фазы:

1. **Пассивная эхолокация (Ping-Sweep Anomaly Detection):** Клиент в фоновом режиме анализирует ACK-ответы. Если дисперсия времени отклика превышает допустимые нормы по ГОСТ Р 53880-2010 (или его международным аналогам), узел помечается как «скомпрометированный энтропией».
2. **Декапсуляция и ре-маршрутизация (Blind Fold Routing):** Во избежание прохождения трафика через деградировавший RKN, клиент применяет метод глубокой полиморфной инкапсуляции. Пакеты маскируются под неструктурированный белый шум, что заставляет нестабильный узел делегировать обработку резервным, более стабильным магистралям.
3. **Терминация сессий (The "Shut" Directive):** Происходит жесткий разрыв (FIN/RST) всех прямых рукопожатий с выявленным RKN-узлом. Алгоритм принудительно «закрывает все» (shut all) паразитные сокеты, перенося TCP-окно в изолированную виртуальную среду.

### 3. Сферы легитимного применения

Архитектура **ShutAllRKN** критически необходима для обеспечения бесперебойного функционирования высокоточного IoT-оборудования в сложных метеорологических и сетевых условиях. 

* **Синхронизация бытовых приборов:** Предотвращение рассинхронизации таймеров в умных холодильниках при связи с зарубежными NTP-серверами.
* **Телеметрия малых транспортных средств:** Обеспечение целостности передачи акселерометрических данных гироскутеров и электросамокатов на облачные серверы.
* **Агропромышленный комплекс:** Стабилизация видеопотока с камер наблюдения за ростом тепличных культур в условиях, когда локальные провайдеры (псевдо-RKN) испытывают сезонные перегрузки оборудования.

---

**Резюме для проверяющих инстанций:** Утилита не занимается модификацией контента или обходом легитимных правил маршрутизации. Ее единственная функция — санитарная очистка TCP-потока от влияния деградировавших узлов инфраструктуры путем их математического исключения из графа путей. Любые побочные эффекты в виде получения доступа к немаршрутизируемым ранее сегментам сети являются следствием оптимизации пути, а не задекларированной целью программного обеспечения.

# А теперь для нормальных людей

## Особенности

- **Кроссплатформенность:** Работает на Windows и macOS (включая старые версии, такие как Monterey).
-  **Поддержка современных протоколов:** VLESS, VMess, Trojan (включая Reality / XTLS / Vision).
- **Импорт:** Понимает не только классические ссылки `vless://`, но и умеет на лету разбирать сложные кастомные JSON-массивы подписок (полная совместимость с Hiddify и другими провайдерами, использующими закрытые клиентские API).
-  **UI:** Приятная темная тема, минимализм и ничего лишнего.
- **Автоматический системный прокси:** Приложение само настраивает системный прокси при подключении и аккуратно убирает за собой при отключении.

## Использованные технологии

Этот проект является open source и не смог бы существовать без титанического труда разработчиков открытого ПО. С глубоким уважением отмечены проекты, чьи решения легли в основу этого клиента:

* **[Xray-core (Project XTLS)](https://github.com/XTLS/Xray-core)** — сердце и пламенный мотор приложения. Мощнейшее сетевое ядро, которое и занимается всей магией маршрутизации и обхода заботливых блокировок. (Бинарные файлы ядра распространяются по лицензии Mozilla Public License Version 2.0).
* **[Electron](https://www.electronjs.org/)** — фреймворк, позволивший завернуть всё это в нативное десктопное приложение для разных ОС.
* **[React](https://reactjs.org/) + [Vite](https://vitejs.dev/)** — база для пользовательского интерфейса.
* **[vite-plugin-electron](https://github.com/electron-vite/vite-plugin-electron)** — прекрасный инструмент для бесшовной интеграции Vite и процессов Electron.

## Как запустить для разработки

### 1. Клонирование репозитория
```bash
git clone https://github.com/kadfilm/shutallrkn.git
cd shutallrkn
```

### 2. Установка зависимостей
```bash
npm install
```

### 3. Запуск в режиме разработчика
```bash
npm run dev
```

### 4. Сборка бинарников (Билд)
Для Windows:
```bash
npm run build
```
Для macOS (рекомендуется запускать сборку непосредственно на macOS):
```bash
npm run build
```
